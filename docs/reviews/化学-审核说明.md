## 审两方面
**一、正确性**（QUALITY 第一部分）：
- 概念、原理、因果、现象和课本、学科共识一致吗？叫法和课本一致吗？有没有说错、说过头的地方？
- 实验步骤、先后顺序、基本操作、注意事项和课本一致吗？
- 模型里的数值、公式、单位、量级对不对？显示给学生的读数、表格、卡片上的数字，按真实化学算出来对不对（写小脚本核算）？示意值有没有标明？
- 画面：颜色、现象（气泡、沉淀、颜色变化、火焰……）的样子和先后对不对？“钻进去看”的微观画面里原子、离子、电子的种类、个数、电荷、去向对不对？
- 做错的后果是不是按模型算出来的、符合真实情况？
- 结论 `conclusion.quote` 是不是课本原文（逐字；“……”只能删去不相干的部分），是不是课本说出结论的那段话（不是步骤、问句、练习题）；`page`/`rect` 截到的是不是这段话；`why`、`formula` 对不对。

**二、操作性**（学生真的能不能做完）：
- 拿放像不像人手在做（DESIGN-化学.md 第二节）：按住就跟手、碰到目标才夹/倒/放、没到目标松手很快放回；有没有松手后自己走一段路线、点一下替人搬运的地方？
- **先用项目里现成的工具**，不要从头写一套拖动脚本：
  - `LB_PORT=<端口> node tools/qa.mjs <id> --flow --demo --mouse`：按步骤栏用真鼠标走完整个流程，含中途插看演示；
  - `LB_PORT=<端口> node tools/flowshot.mjs <id> --upto=<步骤名> [--around=<器材>]`：做到某一步后连拍截图（单张在 /tmp/lbqa/fs/）；
  - `LB_PORT=<端口> node tools/followprobe.mjs <id>`：量按住、拖动、松手时器材跟不跟手；
  - 工具覆盖不到的（某种做错的操作、某个边界情况），再自己写 Playwright 小脚本：playwright 从 `~/.cache/livebook-tools/package.json` 借（`createRequire(`${process.env.HOME}/.cache/livebook-tools/package.json`)('playwright-core')`），打开页面前 stub 掉 WebSocket（见 tools/smoke.mjs），器材的屏幕位置从 `__lb.live.active.inst.debug` 里算，不要凭截图估坐标。
- 按底部步骤栏的提示把每一步做一遍：要拖、要点的东西找得到吗？拖到哪里算数清楚吗？会不会拖不动、点不中、被别的东西挡住？
- 最后可以用 browser use 花几分钟看第一印象（不用它做逐步操作）：像第一次打开的学生那样看几屏，不读说明能不能知道先动什么，有没有挡住、看不清的东西。用不了就跳过。
- 第一次打开的人不读说明，能不能知道先动什么？
- 做错（课本注意事项里的错误）之后，画面里有没有办法改回来、重来？“全部重做”是不是完全回到第一次打开的样子？
- 老师演示：每个动作器材是不是真的动过去？演示结束后学生自己的状态是否原样恢复？
