# 按审稿意见改课

工作区：`<工作区>`。每条命令都先 `cd` 进去。开发服务器 `<端口>` 是大家共用的，不要重启。
标准看 QUALITY.md 和 DESIGN-化学.md。环境、坑、自检的细节，和 `docs/reviews/化学-做课说明.md` 一样。

1. **改哪些**：只改交给你的条目。审稿说错了、要你加课本没有或作者没要的东西（比如新的播放控件、新的功能入口），就不改，在报告里写清理由和依据。
2. **怎么改**：守住 DESIGN-化学.md，尤其是这几条：
   - 拿放要跟手；
   - 卡片写现象，不写评判；
   - 钻进去看要看得清、跟着实验进度；
   - 记录写这一轮真实发生的事；
   - 提示说后果和怎么办。
   
   修一个边界情况，不要把代码越补越复杂；改动要是会带出新的边界情况，在报告里说出来。
3. **能改的文件**：你负责的那几课的课文件，加上它们自己的 parts 文件。公共件只有交给你时写明“归你”的才能改，而且不能改变别的课的行为；改了公共件，用到它的课都要跑一遍 qa。
4. **自检**：
   - 每课单独跑 `LB_PORT=<端口> node tools/qa.mjs <id> --flow --demo --mouse`，都要 1/1 通过；
   - 改到画面的地方，拍全尺寸截图看一遍；
   - 不要 commit。
5. **报告**：简短写。
   - 每一条怎么改的；没改的，写理由。
   - 最后把你新加、改动或删掉的所有面向学生的文字列出来，一条一行。
